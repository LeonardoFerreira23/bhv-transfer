# Documentação Técnica: Behive Transfer API (v1.2.0)**Status do Projeto:** `Funcional / Entrega de Produção (Fase 2)`  **Empresa:** Behive Tecnologia  **Responsável:** Leonardo---## 1. ObjetivoCentralização e padronização do recebimento de vistorias técnicas através de arquivos compactados (.zip, .rar). O sistema visa garantir a integridade dos dados coletados em campo, a organização automatizada no servidor e facilitar a usabilidade do técnico através de interfaces dinâmicas.## 2. Mudança de Escopo (v1.2.0)Nesta versão, a arquitetura foi aprimorada para focar em **Experiência do Usuário (UX) e Segurança**:* **Vantagem:** Fim da digitação manual de UUIDs. O sistema agora abstrai a complexidade do banco de dados utilizando menus suspensos (Dropdowns).* **Blindagem de Código:** Implementação da base da pirâmide de testes com `JUnit 5` e `Mockito`, garantindo a integridade da lógica de upload e geração de links.## 3. Fluxo de DadosO funcionamento do sistema segue as etapas abaixo:1. **Inicialização:** A interface Web consome a API para carregar a lista de Técnicos e Sites ativos.2. **Interface:** O técnico seleciona os dados nos menus e arrasta o arquivo compactado no Dropzone.3. **Processamento:** O Backend recebe os UUIDs de forma invisível, vincula ao pacote e cria a estrutura física de pastas baseada no nome do técnico.4. **Persistência e Link:** O arquivo é salvo no *storage* local da **Behive Tecnologia**, os metadados vão para o PostgreSQL e um link direto de download é gerado e devolvido à interface.---## 4. Endpoints da API### 4.1. Dados Iniciais (Dropdowns)Alimenta a interface do usuário com os dados do sistema.- **URL:** `GET /api/uploads/dados-iniciais`- **Retorno:** JSON contendo arrays de Técnicos e Sites.### 4.2. Upload de Pacote de VistoriaRealiza o envio do arquivo compactado e vincula ao site e ao técnico correspondente.- **URL:** `POST /api/uploads`- **Formato:** `multipart/form-data`| Campo | Tipo | Descrição || :--- | :--- | :--- || `siteId` | `UUID` | Identificador único do Site. || `tecnicoId` | `UUID` | Identificador único do Técnico responsável. || `fotos` | `File` | Arquivo único compactado (.zip ou .rar). |### 4.3. Cadastros BaseEndereços para inserção de novos dados no sistema.- **URL:** `POST /api/tecnicos` - Cadastra novo técnico.- **URL:** `POST /api/sites` - Cadastra novo site.---## 5. Roadmap (Implementações Futuras)Para as próximas versões do **Behive Transfer**, estão planejadas as seguintes evoluções:* **Arquivos Massivos (Chunking):** Implementação de fatiamento de dados para suportar uploads de 1GB+, enviando o pacote em blocos menores de 10MB para evitar queda de rede móvel.* **Dashboard:** Interface administrativa para listagem e download dos pacotes enviados por período ou site.* **Importação em Lote:** Módulo para receber planilhas `.csv` e cadastrar dezenas de sites de uma única vez.---*Documento atualizado em 3 de Maio de 2026.*
